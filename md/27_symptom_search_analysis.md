# 배 아파 의 질문에 5분 넘게 검색함. 결과는 1개 출력


# 증상 검색 처리 분석 보고서: "배 아파" 검색 사례

이 문서는 사용자의 "배 아파" 증상 검색 시 발생한 처리 지연(약 5분) 및 검색 결과 제한(1건)에 대한 기술적 분석 내용을 담고 있습니다.

## 1. 처리 지연 사유 (Performance Analysis)

현재 시스템은 단순 검색이 아닌 **에이전트 기반 검색(Agentic Search)** 흐름을 따르며, 이 과정에서 지연이 발생합니다.

### A. 의도 분석 및 표준화
*   사용자의 자연어("배 아파")를 AI(GPT-4o-mini)가 분석하여 `abdominal_pain`, `stomachache` 등 **영문 표준 의학 용어**로 변환하는 선행 작업이 필요합니다.

### B. 다중 키워드 확장 및 병렬 호출
*   FDA 데이터베이스에서 직접적인 매칭이 부족할 경우, AI가 검색 성공률을 높이기 위해 **유사 키워드를 생성**합니다 (예: Indigestion, Heartburn, Gastritis 등).
*   생성된 **모든 키워드**에 대해 각각 FDA API를 병렬로 호출하며, 호출 횟수가 많아질수록 네트워크 지연 및 서버 응답 대기 시간이 누적됩니다.

### C. 벌크 번역 및 데이터 결합
*   검색된 제품들의 영문 효능(`purpose`) 정보를 사용자에게 보여주기 위해 **AI 벌크 번역**을 수행합니다. 여러 제품의 텍스트를 한꺼번에 처리하는 과정에서 모델 응답 지연이 발생할 수 있습니다.

## 2. 결과 제한 사유 (Result Limitation Analysis)

수많은 데이터 중 최종 결과가 적게 도출된 이유는 시스템의 **안전 정책 및 데이터 필터링** 때문입니다.

### A. 엄격한 OTC 필터링
*   사용자의 안전을 위해 전문의약품을 배제하고 **`HUMAN OTC DRUG`(일반의약품)** 필터를 강하게 적용합니다. 배가 아픈 증상에 쓰이는 강력한 전문의약품(PPI 제제 등)은 이 단계에서 모두 제외됩니다.

### B. 데이터 필드 매칭의 보수성
*   FDA 라벨 데이터의 `indications_and_usage`(효능) 필드는 "배 아픔"과 같은 포괄적 단어보다 "산 역류로 인한 가슴 쓰림 완화"와 같이 **매우 구체적이고 정형화된 문구**를 사용합니다. 키워드 확장에도 불구하고 이 구절들과 정확히 매칭되지 않는 제품들은 결과에서 누락됩니다.

### C. 성분 중심의 결과 집계
*   여러 제품이 검색되더라도 포함된 **활성 성분(Active Ingredient)이 동일**할 경우, 시스템은 중복 정보를 줄이기 위해 성분 단위로 요약하여 보여줍니다. 이 과정에서 사용자에게는 최종적으로 압축된 성분 리스트만 전달됩니다.

## 3. 향후 개선 방향
*   **지능형 캐시(Smart Cache):** 한 번 처리된 증상과 성분 매칭 결과는 Supabase 캐시에 저장하여, 후속 검색 시 수 초 내에 응답하도록 최적화하고 있습니다.
*   **키워드 최적화:** AI가 생성하는 검색 키워드의 우선순위를 조정하여 불필요한 API 호출을 줄이고 정확도를 높일 예정입니다.
